# Project agent memory

This file is the project's committed home for project-intrinsic agent knowledge: build, test, release, architecture, and sharp-edge notes that should travel with the code.

## jev-computer-use

- Scope is slices. Slice 1 is the read-only `jev-cu` CLI (Jev picks a UI candidate or no_match; confidence policy stays in code; nothing is executed); keep its contract and read-only guarantees intact. Slice 2 is `jev-cu-browse`: a generic `CdpAdapter` (`src/cdp/`) plus thin profiles (`src/profiles/`) and the workflow (`src/workflow.mjs`). Keep application knowledge (selectors such as `data-qa` or `data-item-key`, names, allowlists) out of the adapter, transport, and workflow; `test/profiles.test.mjs` fails if they mention Slack or those selectors. The adapter fetches element attributes only for roles a profile declares in `attributeRoles`, and exposes a node's contents text because the real Slack sidebar rows are `treeitem`s whose accessible name Chromium leaves empty (their name is in a `draggable` wrapper) with no link; the synthetic page has a `tree` shape reproducing that (`loadSyntheticPage({ shape: "tree" })`, `serve-synthetic-slack.mjs --shape tree`), so test recognition changes against both shapes. Keep all three page-read text safety checks on the canonical `paragraphEqual` helper in `src/cdp/adapter.mjs`; `slackParagraphs` in `test/fake-cdp.mjs` models the editor's paragraph read-back. New CDP methods go into `ALLOWED_CDP_METHODS` only with a safety reason; arbitrary JavaScript, key events, and navigation methods stay out. Slice 3 is `jev-cu-report`: a read-only Snowflake boundary (`src/snowflake/`, single SELECT only, SQL REST API with key-pair JWT, no SDK), the Unity Data Access queries (`src/unity/data-access.mjs`, official view and column names; QA2 is resolved from `ACCOUNT_GAMES` at run time, never a hard-coded id), and deterministic report/message code (`src/report/`). Every derived number is defined once in `src/report/new-users.mjs` and README "Definitions"; keep them identical. Dry-run is the default; send goes only through `runWorkflow` with `exactDestination` and `duplicateMarker` set. The unattended wrapper is `jev-cu-daily` (`src/schedule/daily.mjs`, `src/schedule/state.mjs`, `bin/jev-cu-daily.mjs`): one post per target date (last complete UTC day), a durable record in `<state-dir>/records/<date>.json` written only after a workflow-verified send, an O_EXCL run lock (stale by boot id / dead pid / 12 h age), and bounded retries with backoff; systemd templates live in `deploy/systemd/` (operator lines marked; `OnCalendar=*-*-* 10:00:00 Asia/Tokyo`, `Persistent=true`). Sharp edges: the `duplicate_post` refusal is terminal but never recorded as success (the marker can sit in an unposted draft), and a swallowed send leaves the draft in the composer, so later runs refuse at insertText until a human clears it. Daily output is scrubbed to statuses and codes only (no counts, message text, destination, or keys); the report's own stdout/stderr are captured and dropped by the wrapper.
- Run offline checks with `npm run lint && npm run typecheck && npm test` (node --test with an injected fake decision dependency, a fake CDP session over `test/fixtures/synthetic-slack-page.json`, and a fixture SQL executor over `test/fixtures/unity-data-access.json` in SQL API encoding; no network; tsc --noEmit over JSDoc types). `.github/workflows/ci.yml` runs the same three checks via `npm ci` on Node 20 and 22 and never calls the real API. A real Jev call needs `TYPESAFE_API_KEY` and the live Snowflake source needs `SNOWFLAKE_*` (README "Snowflake access") in the environment; never print, persist, invent, or commit them, and read them only from the environment. A live CDP smoke uses `scripts/serve-synthetic-slack.mjs` plus a local Chrome (README "Tests and the synthetic page"); never point tests or smoke at a real Slack workspace or post to real Slack, and never run anything but SELECT against Snowflake.
- All four runtime CLI contracts (one JSON object on stdout, statuses, refusal and error codes, exit codes 0/1/2; `--help` is the documented exception) are documented in README.md; keep README and code in sync when changing them.
